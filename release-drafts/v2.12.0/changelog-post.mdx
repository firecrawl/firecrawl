## v2.12.0 is live

Firecrawl v2.12.0 lands a new set of enterprise controls — URL-level threat protection backed by Google Web Risk or a new Zscaler ZIA provider (`mode: "zscaler"`) with per-URL billing, per-team API key IP allowlists, per-key format/endpoint lockdown, per-key usage limits enforced through Autumn (with a fix so per-key denials now correctly surface 402 before a crawl starts), team-ban enforcement at authentication, and replica-safe SIEM Logging over a bounded RabbitMQ queue — plus an opt-in prompt-injection guard on JSON extraction, a new `rawBase64` scrape format for byte-for-byte responses, image OCR that treats raster URLs and uploads as one-page scanned documents (PNG/JPEG/TIFF/GIF/BMP plus JPEG 2000, WebP, and AVIF, with magic-byte routing for mislabeled downloads), session replay for `/v2/interact` with per-tab HLS playlists, per-key concurrency limits on the FoundationDB queue, and a `search` monitor target with a goal-driven LLM judge stack, flat deterministic billing, and stable event dedupe. It also adds a first-party Slack App with a `/monitor` slash command, PHP SDK tool classes for Laravel's AI framework, a `menu` scrape format gated behind `menuBeta`, a hosted parse-upload flow for MCP tools, PDF `totalPages` for truncation detection, per-page PDF markdown (`parsers[pdf].pages`), per-page markers (`parsers[pdf].pageMarkers`) that inline `<!-- page N -->` breaks in `document.markdown`, and typed layout blocks (`parsers[pdf].blocks`) across every SDK, an end-to-end large-PDF story (30–256 MB by-reference transport plus content-level FirePDF job adoption so retries converge instead of restarting, and JS + Python SDK auto-resume on the `processing_continues` timeout signal), an agent `effort` parameter with `/v2/agent` defaulting to `spark-2` and `spark-1` presets silently retiring, a scalable `GET /v2/agent` for paging over runs, agent threads (`GET /v2/agent/threads/:threadId`, `mode: "chat"`, and a `GET /v2/agent/:jobId/skill` endpoint) so a conversation can continue across runs, agent trace/snapshot SDK endpoints, per-endpoint org rate-limit overrides on `TeamFlags`, a `safe` param on `/v2/search`, developer search out of beta plus dedicated JS/Python SDK methods, an anydoc-based document parser rewrite that adds `.docm`, `.ods`, `.odp`, `.xlsm`, `.xlsb`, `.pptx`, `.ppt`, `.pptm`, `.epub`, and `.csv` support, an `enterprise` search parameter across the JS/Python/Ruby/.NET SDKs, a stable `highlights` option on `/v2/search` with a staged rollout, JSON extraction now supported under Zero Data Retention, PDF and document downloads always routed through fire-engine when it's configured (with fire-engine's GCS PDF handoff now accepted on the `POST /scrape` fast path), a new Exchange-routed scrape path plus a `/exchange/*` proxy for provider data sources, a Labs proxy at `/labs/*`, org-scoped blocklist entries, a `SELF_HOSTED_DOMAIN` env var behind reverse proxies, transparent gzip decompression on Fire Engine scrapes, and finishes the migration to Autumn as the single source of truth for credits, concurrency, rate limits, and priority — while dropping the `+4` credit surcharge on enhanced (stealth) proxies.

### Highlights

- **URL-level threat protection** — Enterprise, flag-gated (`threatProtection: "disabled" | "allowed" | "forced"`) domain- and URL-risk classifier that enforces across scrape, batch scrape, crawl, search, map, extract, and agent on v1 and v2. `normal` mode classifies against Google Web Risk's Update API with locally synced hash-prefix lists and per-URL host-suffix × path-prefix expressions, so a flagged page is caught even on an otherwise clean domain. Redirects are re-checked on any URL change, blocked responses raise `unsafe_domain_blocked`, verdicts are never persisted (ZDR), and scans bill at +2 credits per unique URL.
- **Zscaler ZIA threat-protection provider** — A new `mode: "zscaler"` enforces the org's existing ZIA URL policy (selected Zscaler-defined categories plus their own custom URL categories) on every URL Firecrawl accesses, with a lazy per-org sync of the ZIA taxonomy and a Redis-queued, budget-aware inline classification path that stays inside ZIA's 400/hour per-tenant lookup budget. Zscaler-mode decisions are billed at 0 (no scan fee) because classification runs against the customer's own tenant; SIEM `scrape_activity` records `provider: "zscaler-zia"` and a `security_alert` flag when ZIA verdicts carry one.
- **SIEM Logging (replica-safe delivery)** — Scrape activity now streams as batched, AES-256-GCM-encrypted events over a bounded RabbitMQ queue (`siem.logging.events`, capped at 100k with `drop-head` overflow), consumed by index-worker replicas with cross-replica locking, stalled-job recovery, and retry. Threat severity is scoped to the single decision that produced it (categories are no longer unioned across every decision on a scrape), `auditMetadata` is constrained to a required `username` field mapped to ASIM `SrcUsername`, and the Sentinel workspace template now correctly takes a workspace resource ID with the mandatory Monitoring Metrics Publisher role documented.
- **IP allowlists on API keys** — Enterprise `ipRestriction` team flag rejects API-key and OAuth (`fco_`) requests from any IPv4/IPv6/CIDR entry not on the team's `ip_restriction_config` list, with a 60 s Redis-cached lookup, fail-closed semantics, and a dashboard admin cache-clear endpoint. Empty/missing lists remain unrestricted so a team can't lock itself out before configuring.
- **Per-key scope and format lockdown** — Enterprise `keyRestriction` flag lets teams lock individual API keys to allowlists of output formats and endpoint groups — a locked key handed to an agent environment cannot be promptable into fetching raw HTML, using `screenshot` / `scrape` / `executeJavascript` / `pdf` actions, or calling other endpoints. Unknown paths deny by default, v0 is denied outright, and enforcement runs server-side with no per-request override.
- **Per-key usage limits via Autumn** — API-key spend limits (the "Set limit" flow in the dashboard) are now enforced end-to-end: every `checkCredits` call site forwards `apiKeyId` to Autumn, so a request from a key that has exceeded its configured daily/weekly/monthly limit is denied with 402 even when the team as a whole still has credits, and the `checkCreditsMiddleware` clamp no longer rewrites the caller's `limit` up to the team balance when a key-level denial is really the reason Autumn refused the check.
- **Team-ban enforcement** — Banned teams (`teams.banned = true`) are now rejected with 403 at authentication, before rate limiting, via a new `is_banned` field on the ACUC. Historically the ban was enforced by zeroing the ACUC `rate_limits` payload, which quietly became a no-op once authenticated rate limits moved to Autumn.
- **Session Replay for `/v2/interact`** — New `GET /v2/interact/:sessionId/replay` and `GET /v2/interact/:sessionId/replay/:pageId` return per-tab metadata and HLS `.m3u8` playlists (with pre-signed ~6 h segment URLs). Recording is on by default; pass `"recordSession": false` on create to opt out, and `scrape-interact` responses now include `sessionId` so callers can link a job to its replay.
- **Prompt-injection guard for JSON extraction** — Opt-in `checkPromptInjection` on v1 `jsonOptions` and v2 `formats: [{ type: "json", ... }]` runs a dedicated classifier over the scraped markdown (chunked into 100k-character windows) before the extraction call and blocks with `SCRAPE_PROMPT_INJECTION_DETECTED` (403) on detection, so a compromised page can't quietly slip an exfiltration prompt into the extracted output. Billing is +4 credits on top of the JSON surcharge for a clean run, and 5 credits when a provider call was actually dispatched but the request was blocked.
- **`rawBase64` scrape format** — A new output format returns the raw HTTP response body as base64 with no processing (no markdown, no HTML, no transformers). Must be requested exclusively — combining with any other format throws — and is unsupported on `/v2/parse` uploads, `agentIndexOnly`, and `minAge`. Forces `fire-engine;chrome-cdp`, skips actions/waitFor with a warning, and returns `document.rawBase64` alongside response headers.
- **`search` monitor target** — Added a first-class `search` monitor target accepting `queries[]`, `searchWindow`, `includeDomains[]`, `excludeDomains[]`, and `maxResults`, with `raw` (no LLM) and `deep` (LLM judge) depths derived from `judgeEnabled`, a `material_dev` alert mode that re-alerts on material developments of a known event, and stable opaque event keys to prevent label-drift duplicates. Exposed across the JS, Python, Java, .NET, Go, PHP, Ruby, Rust, and Elixir SDKs with a `MonitorSearchTargetResult` type.
- **Slack App** — Connect a Slack workspace and receive monitor alerts as Block Kit summaries, or drive monitors from Slack with the `/monitor` slash command (`watch`, `list`, `cancel`, `status`, `help`). OAuth, signed webhooks, encrypted bot-token storage, auto-join of public channels, and a `notification.slack` block on monitors are all included.
- **PHP SDK Laravel AI tools** — Native `FirecrawlScrape`, `FirecrawlSearch`, `FirecrawlMap`, and `FirecrawlCrawl` tool classes drop into any [laravel/ai](https://laravel.com/docs/13.x/ai-sdk) agent's `tools()` array — same tool names as the MCP server, output size budgets that keep results model-sized, and container-resolved auth reuse. Ships as `firecrawl/firecrawl-php@1.9.0` with the release pipeline now cutting proper Packagist tags.
- **`menu` scrape format** — A new `formats: ["menu"]` returns deterministic structured restaurant-menu data as `document.menu`, mirroring the existing `product` format end-to-end. Beta-gated via the `menuBeta` team flag with a `MENU_EXTRACTION_SERVICE_URL` self-host kill-switch, available across the JS, Python, Java, .NET, Go, PHP, Ruby, Rust, and Elixir SDKs.
- **Image OCR (`parsers[image]`)** — Raster image URLs and image parse uploads are now OCR'd through FirePDF as one-page scanned documents instead of failing with `SCRAPE_UNSUPPORTED_FILE_ERROR`. Rolled out behind the `imageOcr` team flag with a new default parsers list of `["pdf", "image"]`, so a request that says nothing about parsers OCRs images the same way it parses PDFs. Supports PNG, JPEG, TIFF, GIF, BMP, JPEG 2000 (`.jp2` / `.jpx` / `.j2k`), plus WebP and AVIF (including CDN responses that negotiate WebP/AVIF against a `.jpg` or `.png` URL), and magic-byte sniffs mislabeled downloads so a PDF served with an `image/jp2` header now routes to the PDF engine instead of failing. `formats: ["rawBase64"]` still returns raw bytes untouched, and images with no OCR text now return a 200 with empty markdown instead of a hard failure.
- **Hosted `/v2/parse` upload flow** — `POST /v2/parse/upload-url` mints a short-lived, team-scoped `uploadRef` plus signed storage upload parameters; the client uploads bytes directly to GCS; then `POST /v2/parse` accepts JSON with `uploadRef` and parses normally. Refs are HMAC-signed with a 10-minute expiry and bound to team, object path, filename, content type, and max size, so MCP clients can parse local files without exposing an API key to the model or shell.
- **PDF per-page markdown, per-page markers, and typed layout blocks** — `parsers: [{ type: "pdf", pages: true }]` returns per-page markdown as `document.pages: [{ pageNumber, markdown }]`, `parsers: [{ type: "pdf", pageMarkers: true }]` inlines `\n\n---\n\n<!-- page N -->\n\n` between pages in `document.markdown` (no new response field — markdown pipelines get per-paragraph page attribution for free), and `parsers: [{ type: "pdf", blocks: true }]` returns per-page typed layout blocks (`title` / `section_header` / `text` / `table` / `formula` / `figure`, ...) with normalized `bbox`, `readingOrder`, `markdownSpan`, and `confidence`. All three are wired through every first-party SDK.
- **Large-PDF by-reference transport with content-level job adoption** — 30–256 MB PDFs now stream directly into the FirePDF input bucket over a single-pass, sha-hashed upload; base64 body payloads are only used for inline-capable engines. A large-PDF job outlives the caller's polling window on its own page-scaled budget and its result lands in a raw-sha content cache, so a customer's normal retry adopts the in-flight job via `POST /jobs/lookup` and returns the finished document — one processing run per unique document, no client changes. Timeout errors carry `details.state: "processing_continues"`, `documentPages`, `jobStatus`, `estimatedRemainingSeconds`, `retryAfterSeconds`, and an HTTP `Retry-After` header (preferring FirePDF's live remaining-time estimate over the static per-page formula). Fire-engine also gained a GCS handoff path for large PDFs so bytes never re-transit the API when it hands off a matching sha.
- **JS & Python auto-resume for large-document scrapes** — On the `processing_continues` timeout signal, `@mendable/firecrawl-js@4.37.0` and `firecrawl-py@4.40.0` (sync and async) now sleep the advertised `retryAfterSeconds` (clamped 5 s–10 min) and re-issue the request, which attaches to the in-flight FirePDF job and returns the finished document. Bounded at 5 resumes / 20 min total; call-scoped opt-out via `autoResume: false` (JS) / `auto_resume=False` (Python).
- **Agent `effort` parameter and `spark-2` default** — `POST /v2/agent` now accepts `effort: "low" | "medium" | "high"` (mutually exclusive with `model`); every effort level runs `spark-2`, which is also the new default when neither `model` nor `effort` is sent. `spark-1-pro` / `spark-1-mini` remain valid input and silently resolve to `spark-2`. Exposed across the JS (`4.36.0`), Python (`4.39.0`), Rust (`2.17.0`), Go (`1.13.0`), Java (`1.16.0`), PHP (`1.14.0`), Ruby (`1.15.0`), and Elixir (`1.10.0`) SDKs, alongside new `getAgentTrace(jobId, liveView?)` and `getAgentSnapshot(jobId, snapshotId)` methods and typed agent event schema v1.
- **`GET /v2/agent` list endpoint and agent threads** — Added a scalable list endpoint that pages agent runs 20 at a time via an opaque `before` cursor and rejects malformed cursors with 400 instead of silently truncating, plus `GET /v2/agent/threads/:threadId` and a new `mode: "chat"` on `POST /v2/agent` so a conversation can continue across runs by passing back a `threadId` (with typed `thread_not_found` / `thread_busy` / `thread_expired` errors and no orphan request rows on rejected follow-ups). A companion `GET /v2/agent/:jobId/skill` returns a run's generated skill. `listAgents` / `list_agents` and `getAgentThread` / `get_agent_thread` are exposed across every agent-supporting SDK (JS `4.38.0`, Python `4.41.0`, Go `1.14.0`, Rust `2.18.0`, Java `1.17.0`, .NET `1.14.0`, PHP `1.15.0`, Ruby `1.16.0`, Elixir `1.11.0`), with existing calls sending exactly the same body as before.
- **Per-endpoint org rate-limit overrides** — Added `rateLimitOverrides` on `TeamFlags` — a `Partial<Record<RateLimiterMode, number>>` map that replaces the final RPM for the named endpoints only, without moving the whole plan multiplier. Also covers modes with no base entry (`research`, `labs`, `account`); malformed entries are ignored so bad config never breaks authentication.
- **`safe` param on `/v2/search`** — Optional `safe: boolean` on v2 `/search` filters explicit content upstream; omitted requests behave exactly as before. v1 `/search` is untouched.
- **Per-key concurrency limits on the FDB queue** — Added a third gate to the FoundationDB queue's concurrency chain (crawl → key → team → ready) driven by a new nullable `api_keys.concurrency` column. Keys with a limit set hold a per-key slot while queued/active; crawl child jobs inherit the kickoff key so whole crawls stay gated; keys without a limit are fully unaffected.
- **Developer search (GA) plus dedicated SDK methods** — The developer-index search category is out of beta and available at both `POST /v2/developer/search` and the alias `POST /v2/search/developer`, plus a `developer` category on `/v2/search` (now served through the general search flow in the web dashboard). The `developerBeta` gate is removed, and the JS SDK gains `firecrawl.developer.search(...)` (`4.35.0`) and the Python SDK gains `client.developer.search(...)` (`4.38.0`) as first-class methods with normalized transport-error handling.
- **`enterprise` and `threatProtection` in JS & Python SDKs** — The v2 `/search` `enterprise` option now works from JS, Python, Ruby, and .NET (previously silently dropped or mistyped), and the `threatProtection` per-request override is exposed on scrape/batch/crawl/search/map/extract/agent in both JS (`@mendable/firecrawl-js@4.30.0`) and Python (`firecrawl-py@4.32.0`).
- **`highlights` on `/v2/search` (stable, staged rollout)** — Query-relevant highlights on `/v2/search` are now a first-class, stable option: pass `"highlights": true` to force generated highlights, `false` to force provider snippets, or omit it to let the staged rollout decide. The `highlightsBeta` team flag is retired and replaced by a `HIGHLIGHT_ROLLOUT_PERCENT` cohort knob, and the option is wired through every official SDK.
- **anydoc-based document parser** — Rewrote `.doc` / `.docx` / `.odt` / `.rtf` / `.xlsx` / `.xls` handling around `anydoc` and added `.docm`, `.ods`, `.odp`, `.xlsm`, `.xlsb`, `.pptx`, `.ppt`, `.pptm`, `.epub`, `.csv`, plus `.xhtml` as an accepted upload type. Legacy `.doc` now correctly decodes Windows code pages via `\ansicpg` / DOC LID and parses inline formatting, headings, hyperlinks, and tables.
- **Labs proxy (`/labs/*`) and Exchange proxy (`/exchange/*`)** — Two new team-flag-gated pass-through routers: `/labs/*` forwards to `LABS_SEARCH_URL` for the Labs Search catalog and data endpoints (`packs`, `data`, `providers`, `engines`, `research`, `config`), and `/exchange/*` forwards `discover` and `retrieve` to `FIRE_EXCHANGE_URL` under the `exchangeRetrieve` flag, complementing the existing `FIRE_EXCHANGE_URL`-routed provider scrape path.
- **Agent → Browser interop billing** — Browser sessions started by an agent can now be linked to the parent agent request via a signed `__agentInterop` block (`auth`, `requestId`, `shouldBill`) and billed under endpoint `agent` with `jobId = request_id`. Sessions are billed at the **logical release** confirmed by the browser service (frozen `sessionDurationMs`, `cleanupQueued: true`) rather than wall-clock teardown time, and delete responses now return `sessionDurationMs` and `creditsBilled`.
- **Stealth (`proxy: enhanced`) surcharge removed** — Scrapes on an enhanced (stealth) proxy now bill exactly the same as basic ones — a plain markdown scrape with `proxy: "enhanced"` costs 1 credit instead of 5. `auto`-escalated stealth retries and cache-hit replays served from stealth-variant index entries also stop paying the surcharge. JSON-mode scrapes still bill 5.
- **Free research paper endpoints** — `research_paper_search`, `research_related_papers`, `research_paper_read`, and `research_paper_inspect` now bill 0 credits; only GitHub and developer/code searches remain billable through the research proxy.
- **PDF `totalPages` metadata** — PDF scrapes now return `metadata.totalPages` alongside `numPages`, so callers can tell a truncated result (`totalPages > numPages`) from a full parse. Threaded through the API, index cache, and JS/Python SDK types.
- **Exchange-routed data sources (beta)** — With `FIRE_EXCHANGE_URL` configured and the beta flag on, single scrape and crawl requests to provider URLs are served by the Exchange service against a stable provider catalog, billed at the credit cost the Exchange reports, and confirmed back to its ledger. Missing legal terms surface a structured terms response with the provider's key and version. Exchange-delivered content is deliberately excluded from the index cache and search index — every access to provider content flows through the Exchange.
- **Autumn is the single source of truth for credits, concurrency, rate limits, and priority** — Removed the last ACUC-based accounting and quota paths from v0/v1/v2 (including the FirePDF `teamConcurrency` payload, the FDB enqueue gate, and the Slack account status display), retired the `AUTUMN_LIMITS_ENABLED_ORG_IDS` / `AUTUMN_LIMITS_EXPERIMENT_PERCENT` ramp knobs, and pointed the API's ACUC RPCs at `auth_chunk_1` (chunk v58) — which drops the last `concurrency`, `rate_limits`, and `plan_priority` columns from the chunk and adds `is_banned` for the new team-ban enforcement. Autumn `track` calls now set `overageBehavior: "overflow"` so a deduction over the balance is captured in full instead of being silently capped at zero, and Autumn transport errors fail **open** to high fall-back limits so an Autumn outage no longer throttles paid teams down to free-tier defaults.
- **`SELF_HOSTED_DOMAIN` env var** — Self-hosted instances behind a reverse proxy can now set `SELF_HOSTED_DOMAIN` (or send `X-Forwarded-Host`) so crawl status URLs, batch-scrape URLs, parse-upload links, and pagination `next` links use the externally-reachable host instead of the internal bind address.
- **Playwright service runs Chromium as non-root** — The Playwright container now runs Chromium as a non-root user in both Docker Compose and Kubernetes deployments, lowering privileges by default with no behavior change for callers.
- **Follow external-link redirects within their own registrable domain** — Fixed a crawl regression where an external link that redirected within its own registrable domain (e.g. `iana.org/domains/example` → `www.iana.org/help/example-domains`) was wrongly rejected as `CRAWL_DENIAL / EXTERNAL_LINK`; the destination is now followed when it stays on the source's registrable domain (or was found on an in-scope page).
- **Screenshot, PDF actions, and JSON extraction under ZDR** — `formats: ["screenshot"]`, the `screenshot` / `pdf` actions, and `formats: ["json"]` all now work on Zero Data Retention scrapes. Fire Engine writes screenshot and PDF artifacts to a 24 h bucket, the ZDR flag is threaded through smart scrape, the prompt-injection guard, and JSON schema generation so telemetry is suppressed at every model hop, and only the deprecated agent/smart scrape flow (`json.agent`) remains blocked under ZDR.
- **DNS failures now bill 0 credits** — Scrapes that fail DNS resolution no longer bill the 1-credit base charge — DNS failures behave like every other failure class (timeouts, engine failures, TLS errors, blocked pages). `SCRAPE_LOCKDOWN_CACHE_MISS` continues to bill 1 credit.
- **CVE patches** — Resolved multiple CVEs by upgrading `multer` to `2.2.0`, `undici` to `7.29.0` with a major-bound pnpm override, `systeminformation` to `5.31.17` (OS command injection in `networkInterfaces()`), `js-yaml` to `4.3.1` / `3.15.1`, `fast-uri` pinned to `3.1.6`, `qs` to `>=6.16.0`, `postcss-selector-parser` pinned to `6.1.4` in ingestion-ui, `browserslist` to `>=4.28.7`, `autumn-js` to `1.2.55` with a `query-string` `>=9.5.0` override, plus newly disclosed advisories for `brace-expansion`, `shell-quote`, `body-parser`, `postcss`, `nanoid`, `ip-address`, `@faker-js/faker`, and `@humanfs/node`, pulling `@sentry/*` and `@bull-board/*` to their latest patch-secure lines — and removing the malicious `serpapi-python==0.1.5` pin from the GPT-4.1 company researcher example in favor of `google-search-results`.
