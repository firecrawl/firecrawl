# Firecrawl v2.12.0

## Improvements

- **URL-level threat protection** — Added an enterprise, flag-gated (`threatProtection: "disabled" | "allowed" | "forced"`) domain- and URL-risk classifier that enforces across **scrape, batch scrape, crawl, search, map, extract, and agent** on v1 and v2. In `normal` mode requests are classified against Google Web Risk's Update API using locally synced hash-prefix lists (MALWARE, SOCIAL_ENGINEERING, UNWANTED_SOFTWARE) and per-URL host-suffix × path-prefix expressions per the Safe Browsing spec, so a flagged page is caught even on an otherwise clean domain. Redirects are re-checked on any URL change, blocked responses raise `unsafe_domain_blocked` (403 on sync, carried through queued jobs and webhooks), and blocked links inside a crawl are silently skipped with a per-crawl `threat_blocked` counter. Local rules (`whitelist`, `blacklist`, `blockedTlds`, `riskScoreThreshold`, `failurePolicy`, `allowRequestOverrides`) resolve without a paid scan; verdicts are never persisted (ZDR) and only deduplicated in-memory per request/job. Billed at **+2 credits per unique scanned URL**; teams without the flag see zero added latency and no Redis or provider traffic.
- **Zscaler ZIA threat-protection provider (`zscaler` mode)** — Enterprise orgs can now enforce their existing Zscaler Internet Access (ZIA) URL policy — selected Zscaler-defined categories plus their own custom URL categories — against every URL Firecrawl accesses, on top of the local rule set. Custom categories, keywords, and customer additions to Zscaler-defined categories sync into org-local rules lazily behind a distributed lock (default 60 min, "Sync now" endpoint bypasses it), so a non-retaining custom-category allow needs no provider call. Live classifications funnel through one per-org Redis queue with a single drainer and Redis-enforced rate limits so the 1/s and 400/hour per-tenant ZIA budgets hold globally; an exhausted budget or over-deep queue resolves fail-fast through the org's `failurePolicy`. All token and API calls flow through the existing CONNECT-only partner egress proxy (`PARTNER_EGRESS_PROXY_URL`); Zidentity OAuth secrets are AES-256-GCM encrypted at rest with a shared org-secret helper, tokens are memory-only (ZDR), and `mode: "zscaler"` decisions are **exempt from the +2 scan fee** because classification runs against the customer's own tenant. Map results are filtered by local rules only (per-URL classification runs when a scrape starts); SIEM `scrape_activity` records `provider: "zscaler-zia"` plus an optional `security_alert` flag when the ZIA verdict carries one.
- **SIEM Logging** — Added org-scoped SIEM Logging: scrape activity is delivered as a batched, AES-256-GCM-encrypted stream over a bounded RabbitMQ queue (`siem.logging.events`, capped at 100k with `x-overflow: drop-head`), consumed by index-worker replicas, with cross-replica job locking, stalled-job recovery, dedupe, retry, and a `firecrawl_siem_logging_events_total` counter that breaks out `retried`, `dead_lettered`, and `unparseable`. Threat severity is scoped to the single decision that produced it (categories are no longer unioned across every decision on a scrape), so a local-rule deny can't inherit a redirect hop's classifier categories. `auditMetadata` is constrained to one required `username` field mapped to ASIM `SrcUsername`, exposed as a typed field across every SDK. `POST /v2/team/siem/test` now works against a saved-but-disabled destination so the dashboard can gate the enable toggle on a delivered test event, and the Microsoft Sentinel template correctly takes a workspace **resource ID** (with the setup order and the mandatory Monitoring Metrics Publisher role documented) instead of quietly resolving into the deployment's own resource group.
- **IP allowlists on API keys** — Added a per-team API key IP allowlist gated by the enterprise `ipRestriction` team flag. When the flag is on and the allowlist is non-empty, API-key and OAuth (`fco_`) requests from any other IPv4/IPv6/CIDR entry (with IPv4-mapped-IPv6 normalization) are rejected with 403 linked back to the settings page. Allowlists live in the new `ip_restriction_config` table, are read outside the ACUC RPC with a 60 s Redis cache, fail closed on lookup errors, and empty/missing lists remain unrestricted so a team cannot lock itself out before configuring. New `POST /admin/<BULL_AUTH_KEY>/ip-restriction-cache-clear` invalidates a team's cache immediately from the dashboard.
- **Per-key scope and format lockdown** — Added the enterprise `keyRestriction` team flag, which lets a team lock individual API keys to an allowlist of **output formats** and/or **endpoint groups** (`scrape`, `crawl`, `batch-scrape`, `map`, `search`, `extract`, `agent`, `parse`, `browser`, `monitor`, `research`, …). Enforcement runs server-side with **no per-request override** — a locked key handed to an agent environment cannot be promptable into fetching raw HTML, using the `screenshot`/`scrape`/`executeJavascript`/`pdf` actions, or calling other endpoints. Config lives in `key_restriction_config` (one row per `api_key_id`, `allowed_formats` + `allowed_endpoints` jsonb) with a 60 s Redis cache; unknown paths deny by default (fail-closed for future endpoints), v1 alias formats normalize to v2 types, and v0 is denied outright on restricted keys.
- **Per-key usage limits enforced via Autumn** — API-key spend limits (the customer-facing "Set limit" flow in firecrawl-web) are now enforced on the server. Every `checkCredits` call site — the shared `checkCreditsMiddleware` covering scrape/crawl/batch/map/search/extract/agent/monitor/parse on v1 & v2, the v2 `browser` and `scrape-browser` controllers, `fireclaw`, and v0 scrape/crawl/search — now forwards `apiKeyId` in Autumn's check `properties` (mirroring the tracking property already sent). Autumn can now return 402 when an individual key has exceeded its configured daily/weekly/monthly limit, without touching credit balances for the team as a whole. Complements the new `ipRestriction` + `keyRestriction` per-key controls.
- **Team ban enforcement** — Banned teams (`teams.banned = true`) are now rejected with 403 at authentication, before rate limiting. Enforcement moved to a new `is_banned` field on the ACUC (`auth_chunk_1` → `is_banned` mirrors `teams.banned` directly). Historically the ban was enforced by zeroing the ACUC `rate_limits` payload, which quietly became a no-op once authenticated rate limits moved to Autumn.
- **Session Replay for `/v2/interact`** — Added `GET /v2/interact/:sessionId/replay` (with a `/browser/...` alias) returning per-tab replay metadata with `pages`, `pageUrl`, and timings, and `GET /v2/interact/:sessionId/replay/:pageId` returning an HLS `.m3u8` playlist. Playlists are stitched from pre-signed segment URLs that expire (~6 h) — clients re-fetch the playlist to refresh. Recording is on by default; pass `"recordSession": false` on session create to opt out. `scrape-interact` responses now include `sessionId` so callers can link jobs to replays, and replay endpoints return 503 unless `BROWSER_SERVICE_URL` is set.
- **`search` monitor target** — Added a first-class `search` monitor target that runs SERP queries on a schedule and alerts on new or materially-developed results, alongside the existing `url` target. The target accepts `queries[]`, `searchWindow`, `includeDomains[]`, `excludeDomains[]` (exclude wins on overlap), and `maxResults`, with effective depth derived from `judgeEnabled` (`raw` returns SERP hits with no LLM calls when off, `deep` runs the LLM judge stack when on). Goal-versioned URL/event dedupe (keyed on goal + monitor name + queries), stable opaque event keys to prevent label-drift duplicates, cadence re-judging even when SERP snippets are unchanged, and a `material_dev` alert mode that re-alerts only on material developments of a known event. Exposed across the JS, Python, Java, .NET, Go, PHP, Ruby, Rust, and Elixir SDKs with a `MonitorSearchTargetResult` type.
- **Search monitor billing** — Search monitors now bill at a flat, deterministic rate per check: `SEARCH_CREDITS` is charged `ceil(totalResults / 10) * 2`, judged results are charged 1 credit per result (down from 5), and `raw` mode pays nothing for the judge. Deep-mode per-page scrapes flow through the shared scrape pipeline as queued jobs (billed under `CREDITS` like any other scrape) rather than being double-charged on the search check. Actuals are recorded on the check as `flatSearchTargetCredits`, and search-target pages carry 0 per-page credits. Estimates surfaced at monitor create/update include both the search call and a per-result judge allowance.
- **`menu` scrape format** — Added a new `menu` format that returns deterministic structured restaurant-menu data as `document.menu`, mirroring the existing `product` format end-to-end. Beta-gated via the `menuBeta` team flag (teams without the flag get no `menu` field and no error), with a `MENU_EXTRACTION_SERVICE_URL` self-host kill-switch: if the upstream menu engine is unreachable the scrape still succeeds with a `Menu format is not available` warning instead of failing. Exposed across the JS, Python, Java, .NET, Go, PHP, Ruby, Rust, and Elixir SDKs, with the Rust SDK bumped from `2.9.1` to `2.10.0` since `Format::Menu` is a source-breaking addition to its public `Format` enum.
- **Hosted `/v2/parse` file uploads** — Added an authenticated two-step upload flow for parsing local files without exposing a Firecrawl API key to the model or shell. `POST /v2/parse/upload-url` mints a short-lived, team-scoped `uploadRef` plus signed upload parameters; the client uploads bytes directly to storage; and `POST /v2/parse` then accepts JSON with `uploadRef` and reuses the existing parse pipeline. Refs are HMAC-signed with a 10-minute expiry and bound to team, object path, filename, content type, and max size; production storage uses GCS signed POST policies with `content-length-range` enforcement; uploaded objects are best-effort deleted after parse. Multipart `/v2/parse` continues to work unchanged.
- **Slack App** — Added a first-party Slack integration so teams can connect a workspace, receive monitor alerts in a Slack channel, and drive monitors from Slack via a `/monitor` slash command (`watch`, `list`, `cancel`, `status`, `help`, with a bare URL treated as `watch`). OAuth (`POST /v2/slack/oauth/start`, `GET /v2/slack/oauth/callback`) uses Redis-backed state with a TTL and redirect sanitization; management endpoints cover install status, channel listing, and uninstall (`GET /v2/slack/status`, `GET /v2/slack/channels`, `DELETE /v2/slack/installation`); event and command webhooks (`POST /v2/slack/events`, `POST /v2/slack/commands`) verify `X-Slack-Signature` against the captured raw body. Monitor alerts render as Block Kit summaries with strict Slack-limit guards, safe link rendering, auto-join of public channels on first post, and judge-based noise suppression that reads authoritative check counters instead of the truncated page list. Bot tokens are stored AES-256-GCM-encrypted in a new `slack_installations` table (with a `plain:` self-host fallback), and monitors gain a `notification.slack` config (`enabled`, `channelId`, `channelName`).
- **PHP SDK Laravel AI tools** — Added native tool classes for [laravel/ai](https://laravel.com/docs/13.x/ai-sdk) so PHP developers can drop Firecrawl into any Laravel agent's `tools()` array without hand-rolling HTTP: `FirecrawlScrape` (`firecrawl_scrape`), `FirecrawlSearch` (`firecrawl_search`), `FirecrawlMap` (`firecrawl_map`), `FirecrawlCrawl` (`firecrawl_crawl`), and a `FirecrawlTools::all()` helper. Tools implement `Laravel\Ai\Contracts\Tool`, resolve the existing `FirecrawlClient` singleton from the container (config and auth are reused), and treat `laravel/ai` as a suggested dev dependency so the SDK's PHP 8.1 floor is unchanged. Tool outputs are budgeted for model context — scrape truncates at 80k characters, crawl pages at 15k under a 100k whole-result budget, search/map drop tail items with an explicit omitted marker — and crawl runs under one wall-clock deadline with a UUID idempotency key that stays stable across HTTP retries. Ships as `firecrawl/firecrawl-php@1.9.0`, and the release pipeline now pushes proper `v{SDK_VERSION}` tags to firecrawl-php so Packagist finally exposes stable versions (`^1.9` resolves) instead of only `dev-main`.
- **Per-key concurrency limits on the FDB queue** — Added a third gate to the NuQ FoundationDB queue's concurrency chain — **crawl → key → team → ready** — so that jobs enqueued with an API key that has `api_keys.concurrency` set hold a per-key slot while queued/active on top of the existing team and crawl slots. Limits are read on the enqueue path through a 60 s Redis-cached read-replica lookup, apply automatically when every job in the batch (including crawl children, which inherit the kickoff key) shares one `apiKeyId`, and fail open — this is a throttle, not a security boundary. Keys without a limit are fully unaffected: no flag set, no key-gate keys touched, hot path unchanged. Requires the `ALTER TABLE api_keys ADD COLUMN concurrency integer;` migration.
- **PDF per-page markdown (`parsers[].pages`)** — Added an opt-in PDF parser option that returns per-page markdown alongside the flattened document: `parsers: [{ type: "pdf", pages: true }]` populates `document.pages` as `[{ pageNumber, markdown }, ...]` while `document.markdown` still contains the whole document. Page-aware requests are pinned to FirePDF, consume its `pages: [{ page, markdown }]` payload, use versioned capability-specific cache sidecars, and bypass document-only URL index reads/writes so legacy cached artifacts cannot satisfy them. The old `pageMarkdown` request flag is accepted as a deprecated silent alias. Exposed across every first-party SDK with matching version bumps (JS `4.34.0`, Python `4.37.0`, Go `1.11.0`, Java `1.14.0`, Ruby `1.13.0`, PHP `1.12.0`, Rust `2.14.0`, .NET `1.12.0`).
- **PDF typed layout blocks (`parsers[].blocks`)** — Added a companion `parsers: [{ type: "pdf", blocks: true }]` option that returns per-page typed layout blocks (`title`, `section_header`, `text`, `table`, `formula`, `figure`, …) with normalized `bbox` coordinates, `readingOrder`, a `markdownSpan` back into `document.markdown`, and `confidence` for layout and OCR. `document.blocks` is populated by FirePDF's existing `include_blocks` path (shipped there in July, never exposed on the API before). Also exposed across every first-party SDK with version bumps.
- **`safe` param on `/v2/search`** — Added an optional `safe: boolean` parameter to v2 `/search`. When `true`, explicit content is filtered upstream; omitted requests behave exactly as before, so existing cache keys and provider requests are unchanged for anyone who doesn't opt in. v1 `/search` is untouched.
- **`SELF_HOSTED_DOMAIN` env var** — Self-hosted instances behind a reverse proxy can now set `SELF_HOSTED_DOMAIN` to the externally-reachable host, fixing crawl status URLs, batch-scrape URLs, parse-upload links, and pagination `next` links that previously pointed at the internal bind address (e.g. `http://localhost:3002`). The resolver also honors `X-Forwarded-Host` and preserves ports; cloud behavior is unchanged when neither is set.
- **Autumn is the single source of truth for credits, concurrency, rate limits, and priority** — The last ACUC-based accounting and quota paths are gone. Autumn now unconditionally sources authenticated rate limits (`base × multiplier` via `getAutumnRateLimiter`), team concurrency (via `getEffectiveConcurrencyLimit` on every controller and on the FDB enqueue gate), and job scheduling priority (inferred from the Autumn multiplier), with ACUC used only as a fall-back when Autumn cannot answer; the `AUTUMN_LIMITS_ENABLED_ORG_IDS` / `AUTUMN_LIMITS_EXPERIMENT_PERCENT` ramp knobs are removed. The FirePDF async-path `teamConcurrency` payload and the Slack `/firecrawl account` display both read Autumn, with the Slack numerator switched to the combined Redis+FDB active count so `active / limit` matches `/v2/concurrency-check` for FDB-migrated teams. Autumn `track` calls now set `overageBehavior: "overflow"` so a deduction over the balance is captured in full instead of being silently capped at zero, and Autumn transport errors fail **open** to high limits (concurrency 100, rate multiplier 100) so an Autumn outage no longer throttles paid teams down to free-tier defaults.
- **Developer search category (GA)** — The developer-index search category (renamed from "code search") is now generally available and served at both `POST /v2/developer/search` and the alias `POST /v2/search/developer`. The `developerBeta` team flag is removed, results log to the `code_searches` ledger, category input aliases and a `skills` parameter are accepted, and `web` search now preserves upstream `position` and prefers upstream titles for developer results. Exposed across the JS, Python, and other first-party SDKs.
- **Labs proxy (`/labs/*`)** — Added an authenticated, team-flag-gated pass-through proxy at `/labs/*` that forwards to `LABS_SEARCH_URL` for the Labs Search catalog and data endpoints (`GET /labs/search/engines`, `providers`, `packs`, `PATCH /labs/search/packs/:packId`, `POST /labs/search/data/pages`, `PATCH /labs/search/data/:sourceId`, `POST /labs/search/data/:sourceId/refresh`, plus the sibling `research` and `config` endpoints). Requires the `labsSearch` team flag; the proxy attaches a shared secret and forwards headers verbatim without additional credit checks (billing happens downstream). Rate-limited under a new `RateLimiterMode.Labs` (limit `1000`).
- **Exchange proxy routes** — Added `POST /exchange/discover` (10 s upstream timeout) and `POST /exchange/retrieve` (50 s) forwarding to `FIRE_EXCHANGE_URL` for teams with the `exchangeRetrieve` flag. Requests get `504` on timeout, `502` on upstream failure, `503` when the upstream is unconfigured, and `403` when the flag is off. Complements the existing `FIRE_EXCHANGE_URL`-routed provider scrape path.
- **Agent → Browser interop billing** — Browser sessions started by an agent can now be linked to the parent agent request and billed against it. `POST /v2/browser` accepts a signed `__agentInterop` block (`auth`, `requestId` UUID, `shouldBill`), which persists `browser_sessions.request_id` and `browser_sessions.should_bill`; billing is attributed to the parent under endpoint `agent` with `jobId = request_id`, and `shouldBill: false` bypasses both the credit pre-check and the ledger write. Delete responses now include `sessionDurationMs` and `creditsBilled`, and browser sessions are **billed at the logical release confirmed by the browser service** (frozen `sessionDurationMs`, `cleanupQueued: true`) — the delete returns `502 Browser session release was not confirmed` when the browser service can't confirm durable cleanup, so wall-clock teardown time no longer inflates the charge. Requires `AGENT_INTEROP_SECRET` (non-blank, no lone UTF-16 surrogates); interop calls with the flag unset are rejected `403`.
- **Free research paper endpoints** — `research_paper_search`, `research_related_papers`, `research_paper_read`, and `research_paper_inspect` now bill 0 credits; only GitHub and developer/code searches remain billable through the research proxy. Ledger writes for developer/code searches record actual billed credits (0 in preview mode instead of a placeholder).
- **Stealth (`proxy: enhanced`) surcharge removed** — Scrapes that run on an enhanced (stealth) proxy now bill exactly the same as basic ones — a plain markdown scrape with `proxy: "enhanced"` costs **1 credit**, not 5. The old flat `+4` add-on was dropped from the real charge path, the keyless free-tier reservation, and the monitor per-check estimate and actual-credits fallback. `auto`-escalated stealth retries, cache-hit replays served from the stealth-variant index, and blocked-but-billed pages also stop paying the surcharge. JSON-mode scrapes still bill 5, and the lockdown / question / highlights / audio / video / redactPII / unblocked-domain / ZDR / x-twitter add-ons are untouched.
- **anydoc replaces the custom document parser** — Rewrote `.doc`, `.docx`, `.odt`, `.rtf`, `.xlsx`, `.xls` handling around `anydoc` (now at `0.2.0`), and added first-class support for `.docm`, `.ods`, `.odp`, `.xlsm`, `.xlsb`, `.pptx`, `.ppt`, `.pptm`, `.epub`, `.csv`, plus `.xhtml` as an accepted upload type. Content-type and extension detection is centralized in `apps/api/src/lib/document-formats.ts` (used for upload sniffing, URL-path routing, and scrape classification); the document engine converts markdown to safe HTML via `safeMarkdownToHtml`. Legacy `.doc` now parses formatting: MS-DOC FKP bin tables produce headings, inline bold/italic/strikethrough, and hyperlinks; Windows code pages are decoded via `\ansicpg` / DOC code page / LID with `encoding_rs` fallbacks; OLE `\x05SummaryInformation` and DOCX/ODT metadata are read through shared XML helpers with BOM stripping.
- **PDF parser upgrade (`pdf-inspector` 0.1.0 → 1.14.2)** — Native PDF processing (`detectPdf` / `processPdf`) picks up parser resource bounds, Form XObject operator support, and small-caps table merging. `PdfOptions` / `process_pdf_with_options` are unchanged.
- **External-Request-Id passthrough** — Integrations that stamp their proxied requests with an opaque `External-Request-Id` header now have it stored on the `requests` row keyed by the same id billing carries as `jobId`, so downstream billing/usage attribution can join back to the integration's own operation. Trimmed, capped at 2048 bytes, sanitized against null bytes, threaded through every v0/v1/v2 request-receipt path (scrape, crawl, batch scrape, search, map, extract, parse, agent, browser, interact, research, llmstxt, deep research). Oversize headers drop to null with a warning — a customer's request never fails over telemetry.
- **`fco_` / `fcmcp_` OAuth credentials** — The auth layer now validates opaque `fco_` credentials through the Web authorization server on every request (audience-checked, credential-purpose-checked — `general` or `hosted_mcp_oauth`) and mints short-lived `fcmcp_` delegated credentials for internal Core calls with a dedicated signing secret. Managed backing keys are read from the primary DB and bypass the API-key cache so revocation is visible immediately; transport or upstream introspection failures return `503`, while inactive or wrong-audience credentials return `401`. Raw managed backing keys are rejected as REST API keys. Feature-flagged off until rollout.
- **Follow external-link redirects within their own registrable domain** — With `allowExternalLinks: true`, a discovered external link that redirected within its own registrable domain (e.g. `iana.org/domains/example` → `www.iana.org/help/example-domains`) was previously rejected as `CRAWL_DENIAL / EXTERNAL_LINK`; the destination is now followed when it stays on the source's registrable domain (or on an in-scope page). Uses the PSL-based `is_subdomain` check.
- **Playwright service runs Chromium as non-root** — The Playwright container now runs Chromium as a non-root user, lowering privileges by default in both Docker Compose and Kubernetes deployments. No behavior change for callers.
- **`threatProtection` option on JS & Python SDKs** — Exposed the v1/v2 `threatProtection` per-request override in `@mendable/firecrawl-js` (4.29.2 → 4.30.0) and `firecrawl-py` (4.31.0 → 4.32.0), matching the API's `threatProtectionOverrideSchema` exactly: `mode` (`off`/`normal`), `riskScoreThreshold` (0–100), `blacklist`, `whitelist`, `blockedTlds`, `failurePolicy` (`open`/`closed`). Accepted on scrape, batch scrape, crawl (via `scrapeOptions`), and top-level on search, map, extract, and agent in both SDKs; the Python `crawl` / `start_crawl` `threat_protection` kwarg is lifted into `scrapeOptions.threatProtection` on the wire; the JS SDK also omits `threatProtection` from `ParseOptions` so it can't leak into `/v2/parse` bodies.
- **`enterprise` search parameter across SDKs** — Wired the `/v2/search` `enterprise` option through the JS, Python, Ruby, and .NET SDKs so callers can select enterprise search modes (`["zdr"]` / `["anon"]`). Previously JS and Python silently dropped the field, and .NET typed it as `bool?` and serialized incorrectly. Ships as `@mendable/firecrawl-js@4.29.0`, `firecrawl@4.31.0` (Python), `firecrawl@1.10.0` (Ruby), and `firecrawl-sdk@1.9.0` (.NET). The Elixir SDK already wired this correctly.
- **PDF `totalPages` metadata** — PDF scrapes now expose a `metadata.totalPages` field carrying the document's true page count before any `maxPages` capping, so callers can tell a truncated response from a fully-parsed one. `totalPages > numPages` unambiguously signals truncation; the field is omitted when the true count is unknown (native detection failed), mirroring how `title` is handled. Threaded end-to-end through the PDF engine, v1/v2 response schemas, the GCS index cache, and the JS/Python SDK types.
- **`highlights` on `/v2/search` (stable, staged rollout)** — Query-relevant highlights on `/v2/search` are now a first-class, stable option: pass `"highlights": true` to force generated highlights, `false` to force provider snippets, or omit it to let the staged rollout decide. The `highlightsBeta` team flag is retired; a new `HIGHLIGHT_ROLLOUT_PERCENT` (0–100) returns generated highlights for a stable per-caller cohort of non-MCP/CLI traffic and runs the remainder in shadow mode, replacing the previous `HIGHLIGHT_SHADOW_RATE` / `HIGHLIGHT_SHADOW_MAX_INFLIGHT` knobs. Every indexed web and news result is sent to the model service in a single `/batch_highlight` request via a shared indexed-Chain helper, mapped back by stable page ID; missing or empty highlights fall back to the provider snippet (never a blank result), transient failures retry, and request IDs propagate through logging. Wired through all official SDKs.
- **Transparent gzip decompression** — Fire Engine scrapes now detect gzipped payloads by magic bytes and transparently decompress them via `gunzipSync` before parsing, with a 50 MB decompressed-size cap; size or decompression failures raise `UnsupportedFileError`. `application/gzip` is no longer excluded from specialty routing, so gzipped documents flow through the normal pipeline.
- **JS SDK `webhook` option on extract** — `startExtract` and `extract` in `@mendable/firecrawl-js` now accept `webhook?: string | WebhookConfig | null`, matching `crawl` and `batchScrape`. Callers can pass a URL string or a full webhook config with metadata and events, and it is forwarded to the request body.
- **`proxy: enhanced` / `stealth` engine selection** — Fixed `proxy: enhanced` and `proxy: stealth` silently falling back to non-stealth engines on the cloud — fallback selection now filters down to stealth-capable engines when stealth is requested, so the user's choice is actually honored. Self-hosted deployments without fire-engine keep working because the guard preserves the original engine list when no stealth-capable engine qualifies.
- **NuQ FoundationDB metrics** — Added FDB queue gauges alongside the existing NuQ metrics. `nuq_fdb_queue_<queue>_job_count` reports per-status counts (`queued`, `active`, `backlog`, `completed`, `failed`), `firecrawl_nuq_fdb_pending_jobs` exposes a worker-load gauge for autoscaling, and a new `GET /admin/<BULL_AUTH_KEY>/nuq-fdb-metrics` endpoint serves them in Prometheus format.
- **ACUC RPC bumped to `auth_chunk_1`** — Pointed the API's `auth_credit_usage_chunk` RPCs at the renamed `auth_chunk_1` / `auth_chunk_1_from_team` (chunk v58). That chain carries every prior v50 → v57 accumulation — single-team orgs use `GREATEST(override, plan)` concurrency, pay-as-you-go orgs get a concurrency floor of 5, per-team `rate_limits` overrides merge with the base plan per-endpoint, multi-team-org fallback resolves plan-less teams to Scale/Enterprise limits, `organization_data_source_terms` and `is_extract` land on the flags payload — and v58 finally drops `concurrency`, `rate_limits`, and `plan_priority` from the chunk. `org_id` remains on the chunk directly. Deploy the corresponding `firecrawl-db` migration first.
- **Autumn-sourced rate limits, concurrency, and priority** — Rate limits, concurrency, and job scheduling priority are now sourced unconditionally from Autumn, with ACUC as a fall-back when Autumn cannot answer. The prior `AUTUMN_LIMITS_ENABLED_ORG_IDS` / `AUTUMN_LIMITS_EXPERIMENT_PERCENT` ramp knobs and the ACUC concurrency/`rate_limits`/`plan_priority` read paths are removed.
- **Org-scoped URL blocklist entries** — The internal blocklist now accepts per-org rows in addition to the existing global rows. Rows with `org_id NULL` continue to block for everyone; rows with `org_id` set block only that org's teams. Enforcement threads through every scrape-shaped path (scrape, crawl, batch, extract, search, deep research, LLMs.txt, monitors), and org-restricted requesters opt out of the shared LLMs.txt cache on both read and write so cached content can't leak past a per-org block. Requires the `ALTER TABLE blocklist ADD COLUMN org_id uuid;` migration.
- **Exchange-routed data sources (beta)** — Reimplements the removed data-layer scrape path against the Exchange service. When `FIRE_EXCHANGE_URL` is set and the org has the beta flag, single scrape and crawl requests to provider URLs (matched on the Exchange's provider catalog with path-segment boundaries) are served from the Exchange, billed at the per-response credit cost the Exchange reports, and confirmed back to its ledger so accounting reconciles. The provider catalog is prefetched at boot and served stale-while-revalidate, so flagged-org requests never block on a catalog fetch; an Exchange outage degrades an eligible request to normal-blocklist behavior instead of failing the customer. Terms-required responses carry the provider's terms key and version from the catalog. Exchange-delivered documents are excluded from the index cache and search index — every access to provider content must flow through the Exchange and its ledger. Batch scrape, `atsv`, `minAge`, `includeTags`/`excludeTags`, profile-backed scrapes, and non-scrape-shaped routes (map, search, monitors) all keep plain blocklist behavior.
- **Branding — declared marks, LLM failure fallback, brand-color picking** — Branding profiles now surface a top-level `brandName` (from `og:site_name` / title / h1 / domain, mirroring `images.logo` onto `logo` for convenience) and prefer chromatic CTA/brand colors over near-black nav chrome when picking `colors.primary`, applying LLM color roles at the same 0.5 confidence bar as buttons. The candidate pipeline now considers site-declared brand marks (JSON-LD `Organization.logo`, apple-touch icons) as first-class candidates rather than a last-resort fallback, and a transient LLM failure no longer erases a confident heuristic pick (the failure fallback drops its zero-confidence `logoSelection` / fabricated `personality` / `designSystem`, so the transformer's existing restore path promotes the heuristic). Branding-only scrapes (where `blockMedia: false` exists purely for logo discovery) also carry a `forceNonRender` hint so they stay on the standard browser engine, avoiding scrape timeouts on visually-heavy pages. Exposed as `brandName` in the JS SDK (`@mendable/firecrawl-js@4.32.2`) and `brand_name` in Python (`firecrawl-py@4.35.1`).
- **Screenshot and PDF actions under Zero Data Retention** — `formats: ["screenshot"]` and `actions: [{ type: "pdf" }]` / `[{ type: "screenshot" }]` now work on ZDR scrapes. Fire Engine writes the artifacts to a bucket with a 24 h deletion policy, so the API-side ZDR gate is removed; the DB record is still scrubbed and no job payload lands in the persistent jobs bucket.
- **Keyless quota exhaustion telemetry** — Keyless quota-exhaustion responses (middleware limit and projected-credit reservation limit) now emit a versioned HMAC `conversionCohort` in logs (never in the API response), gated by a required `KEYLESS_CONVERSION_HMAC_SECRET` (≥ 32 chars), so conversion analytics can join without adding raw-IP persistence. - Added `keyRestriction: boolean` to `TeamFlags`. When on, individual API keys can be locked to allowlists of output formats and endpoint groups (`scrape`, `crawl`, `batch-scrape`, `map`, `search`, `extract`, `agent`, `parse`, `browser`, `monitor`, `research`, …) via `key_restriction_config` (`api_key_id`, `allowed_formats` jsonb, `allowed_endpoints` jsonb). Enforcement runs in `supaAuthenticateUser` (unknown paths deny) and post-parse in every scrape-output controller — v1 alias formats normalize to v2 types (`screenshot@fullPage` → `screenshot`, `extract` → `json`), and the `screenshot` / `scrape` / `executeJavascript` / `pdf` actions are rejected when their equivalent formats are not allowed. v0 is denied outright on restricted keys. Value comes from the resolved `req.acuc.api_key_id`, falls back to `null`, and matches the property already sent on the tracking path.
- Added a per-key concurrency limit to the FDB queue via a new nullable `api_keys.concurrency` integer column. When set on a key, jobs enqueued with it hold a per-key slot on top of team and crawl slots (crawl → key → team → ready), the limit is refreshed on the enqueue path through a 60 s Redis-cached read-replica lookup, and crawl child jobs inherit the kickoff's `apiKeyId` so whole crawls stay gated. Keys without a limit are untouched.

Field shape mirrors the API's `threatProtectionOverrideSchema`: `mode` (`off`/`normal`), `riskScoreThreshold` (0–100), `blacklist`, `whitelist`, `blockedTlds`, `failurePolicy` (`open`/`closed`).

- Added `highlights?: boolean` to `POST /v2/search` and `POST /v1/search`. The `highlightsBeta` team flag is removed. Every indexed web and news result is sent in a single `/batch_highlight` request via a shared indexed-Chain helper (`runIndexedSearchHighlights`), with provider snippets preserved on missing/empty outputs and the legacy sentence-split pipeline removed. Exposed as `highlights?: boolean` on the search request in the JS (`@mendable/firecrawl-js@4.30.1`), Python, Ruby, .NET (`firecrawl-sdk@1.9.1`), Java, Go, PHP, Rust, and Elixir SDKs.
