# Firecrawl v2.12.0

## Improvements

- **Alexandria provider tools** — Discover and execute third-party provider tools directly through Firecrawl. `POST /v2/search` with `sources: ["alexandria"]` returns tool contracts in `data.tools`, `POST /v2/scrape` with `domainTools: true` attaches tools matched to the scraped page's domain, and `POST /v2/scrape` with an `alexandria` body executes one to ten provider calls and returns results in `data.alexandria[]`. Discovery is free; execution bills through the standard rails with idempotent replays keyed on `x-request-id`. Available in the JavaScript, Python, Go, and Rust SDKs.
- **Safe Mode** — Added an organization-level Safe Mode enforced across `/scrape`, `/crawl`, `/batch/scrape`, `/search`, `/map`, `/extract`, `/interact`, and `/monitor`. Blocked options return `403 SAFE_MODE_BLOCKED`, restricted sites return `SCRAPE_SITE_RESTRICTION_BLOCKED`, and `lockdown: true` runs cache-only with no robots, sitemap, or live discovery and zero data retention by default. Includes worker-side backstops that strip profiles, login actions, credential headers, and URL-embedded Basic Auth.
- **`menu` scrape format** — Added a deterministic structured `menu` format that returns restaurant menu data on `document.menu`. Available in all 9 SDKs and gated behind the `menuBeta` team flag; requests without the flag succeed silently with no `menu` field.
- **Interact Session Replay** — Added HLS-based session replay for `/v2/interact` and `/v2/browser` sessions. `GET /v2/interact/:sessionId/replay` lists recorded tabs and `GET /v2/interact/:sessionId/replay/:pageId` returns an `.m3u8` playlist with pre-signed segments (~6h expiry). Session creation accepts `recordSession` (default `false` — opt in with `recordSession: true`), and interact responses include `sessionId` for linking replay URLs.
- **Zero-data-retention Interact sessions** — `/v2/interact` and `/v2/browser` now accept `zeroDataRetention: true`, and forced-ZDR teams get it automatically. The policy is stored on the session and inherited by every subsequent execution and scrape continuation. Recording and saved profiles are rejected for ZDR sessions, request bodies are stripped from credit denial and clamping logs, and prompts route through a non-logging GPT-6 Luna provider with telemetry disabled.
- **Threat Protection** — Added an enterprise `threatProtection` policy (`disabled` / `allowed` / `forced`, modes `off` / `normal` / `zscaler`) that classifies scrape, crawl, search, map, extract, and agent URLs through Google Web Risk or a Zscaler ZIA provider. Unsafe pages are blocked with a consistent 4xx and billing dedupes per canonical URL at `+2` credits per scanned URL.
- **IP Restriction** — Added a per-team API key IP allowlist (IPv4, IPv6, CIDR) gated by the `ipRestriction` team flag. Enforced in authentication for API-key and `fco_` OAuth tokens using `req.ip`; unlisted IPs return `403`, with a 60-second Redis cache on the allowlist.
- **API key scope lockdown** — Added a `keyRestriction` team flag that locks individual API keys to allowlists of output formats and endpoint groups (`scrape`, `crawl`, `search`, `agent`, `parse`, …). Enforcement is server-side with no request-side override, unknown paths fail closed, and `screenshot` / `pdf` / `scrape` / `executeJavascript` actions are gated by their corresponding format allowlist.
- **SIEM Logging** — Added organization-scoped SIEM Logging that delivers scrape activity events to third-party destinations through a shared, replica-safe BullMQ queue with retries, stalled-job recovery, and per-delivery credential reloads. Includes a Microsoft Sentinel artifact under `apps/siem/azure-sentinel`.
- **Agent list endpoint** — Added a scalable `GET /v2/agent` with `before` cursor pagination, a `next` URL only when more pages exist, and hidden/starred/labeled run metadata scoped to the authenticated team. Each item now also carries `options.threadId` and `options.threadTurn` so threads can be reconstructed. Added `listAgents` / `list_agents` methods to the JavaScript, Python, Go, Rust, Java, .NET, PHP, Ruby, and Elixir SDKs.
- **Agent incomplete results** — `GET /v2/agent/:id` now exposes best-effort partials and credit-stop metadata on failed runs through `partial`, `partialSchemaValid`, and `stopReason`, so a run that halts on credits or a tool error no longer forces callers to retry blind. The JavaScript and Python SDKs preserve the new fields on the status response and the thread history.
- **Agent `effort` parameter** — Added `effort: "low" | "medium" | "high"` to `POST /v2/agent`, mutually exclusive with `model`. `effort` alone runs against `spark-2` at the requested reasoning budget; the value is echoed on the status response. Available in every agent-supporting SDK.
- **Agent `exchange.onTermsRequired`** — Added an optional `exchange.onTermsRequired: "skip" | "ask"` on `POST /v2/agent` so callers can choose whether a run skips providers with unaccepted data terms or pauses for approval. Follow-up turns inherit the thread's previous value; `AgentExchangeSummary` carries `onTermsRequired`, `skippedProviders`, and a `requiresAction` approval id, and `AgentPendingApproval` is now a `calls`/`terms` union.
- **Agent exchange and threading across every SDK** — The JavaScript, Python, Go, Rust, Java, .NET, PHP, Ruby, and Elixir SDKs now accept `exchange`, `threadId`, and `mode` on `POST /v2/agent` and preserve them on the status response, bringing every SDK to parity with the JS and Python agent surface.
- **Agent traces and snapshots in SDKs** — Added `getAgentTrace(jobId, liveView?)` (`GET /v2/agent/:id/trace`) and `getAgentSnapshot(jobId, snapshotId)` (`GET /v2/agent/:id/snapshots/:snapshotId`) across the JavaScript, Python, Rust, Go, Java, PHP, Ruby, and Elixir SDKs.
- **Agent response hints** — v2 `/scrape`, `/search`, `/parse`, and `/map` can now return an opt-in `agent_hints: string[]` field driven by a deployment-configured external provider that supplies response-guidance rules. Hints are computed deterministically from signals already in memory — endpoint, success, remaining credits, page status, redirect depth, PDF page counts, web-result excerpts and origins — with no extra model calls or page scans. Callers opt in per request with `X-Firecrawl-Agent-Hints: true`; each response carries at most three hints. Self-hosted deployments without a configured provider see no `agent_hints`.
- **`GET /v2/parse/formats`** — Added a read-only endpoint that lists every upload type `/v2/parse` accepts, with the format id, `kind` (`document` / `image`), file extensions, MIME types, and an `available` flag per deployment. Clients no longer need to mirror `document-formats.ts` and `image-formats.ts`. Shipped in the JavaScript, Python, Go, Rust, Java, .NET, PHP, Ruby, and Elixir SDKs.
- **`gov` search category** — Added a `gov` category on `POST /v2/search` and a dedicated `POST /v2/search/gov` endpoint that return government-source web results in `data.web` with no SERP noise, mirroring the shape of the `developer` category. Gov results are free (0 credits) and keyless-friendly. Available as `search(..., categories: ["gov"])` and as a dedicated `searchGov()` method on the JavaScript SDK.
- **Auto-resume for large-document scrapes** — The JavaScript and Python SDKs now transparently resume `/scrape` calls when the API returns `details.state: "processing_continues"`, honoring the payload's `retryAfterSeconds` (clamped 5s–10m) with a bound of 5 resumes and 20 minutes of total wait. Opt out with `autoResume: false` (JS) or `auto_resume=False` (Python).
- **Prompt-injection guard for JSON extraction** — Added an opt-in `checkPromptInjection` boolean to v1 `jsonOptions` / `extract` and v2 `formats: [{ type: "json", … }]`. When enabled, a dedicated classifier scans scraped content before the extraction call and fails fast with `SCRAPE_PROMPT_INJECTION_DETECTED` (`403`) on detection. Adds `+4` credits when the check runs cleanly.
- **PDF page attribution** — Added `parsers[{ type: "pdf", pageMarkers: true }]` to inline per-page markers directly in `document.markdown`, plus `parsers[].pages` for a per-page markdown array and `parsers[].blocks` for typed PDF layout blocks. Renamed the earlier `pageMarkdown` option to `pages`.
- **Image OCR** — Added default image OCR through FirePDF for raster PNG, JPEG, WebP, AVIF, and JPEG 2000 inputs; images route through the image parser and return a one-page document. Rolled out per deployment via `IMAGE_OCR_ENABLED`.
- **Legacy `.doc` formatting** — Improved MS-DOC parsing to preserve inline styles (bold, italic, strikethrough), headings from outline levels, hyperlinks, and tables instead of returning flat text.
- **`anydoc` document parser** — Replaced the custom document parser with `anydoc`, a Rust-based engine that standardizes DOCX, DOC, ODT, RTF, XLSX, XLS, and HTML inputs to Markdown across the parse and scrape paths. Adds byte-level format detection with an extension fallback.
- **Browser profile listing** — Persistent browser profiles created through the API, CLI, or MCP now show up in the dashboard. The API records each session's profile name and upserts `browser_profiles` rows when the browser service reports `profile.saved`. Also added `DELETE /v2/browser/profiles/:name` (and `/v2/interact/profiles/:name`) to delete a profile's saved state and its listing row.
- **Configurable ad blocking for browser sessions** — Added `blockAds: boolean` (default `true`) on `POST /v2/browser` so interact and browser sessions can opt out of the always-on ad, tracker, and cookie-popup blocker. New Interact sessions inherit the scrape's `blockAds`; sessions adopted via `existingSessionId` keep their own setting.
- **`safe` search parameter** — Added an optional `safe: true` on `POST /v2/search` that filters explicit content upstream. Omitted requests are unchanged.
- **Search `objective` and `clientModel`** — Added optional `objective` and `clientModel` fields on `POST /v2/search`. The values are stored with the request for ranking and quality signal use; invalid values are ignored rather than rejected so existing callers are unaffected.
- **`rawBase64` scrape format** — Added `rawBase64` to v2 scrape formats, returning the raw response payload as a base64 string alongside the other document fields.
- **Developer / Code Search out of beta** — Removed the `developerBeta` entitlement gate so `POST /v2/search` accepts the `developer` category and `POST /v2/developer/search` works for every team. Aliases for the `developer` category (e.g. `code`) are accepted on input.
- **Abortable JS SDK `crawl()`** — The JavaScript SDK's `crawl()` now accepts an `AbortSignal`; aborting stops polling, sends a best-effort cancel for the job so the server does not keep spending credits, and rejects the promise with `signal.reason`. `cancelCrawl()` now returns `false` on a `409` (job already completed) instead of throwing.
- **Python SDK crawl cancellation** — The async `crawl()` now cancels its server-side job when the awaiting task is cancelled (for example by `asyncio.timeout` / `asyncio.wait_for`), stopping credit spend. `cancel_crawl` returns `False` on a `409` in both the sync and async clients, and a wait timeout raises a `CrawlJobTimeoutError` (a `TimeoutError` subclass with `job_id` and `timeout`) so the caller still has the id.
- **Python SDK `CrawlJob` id and warning** — `firecrawl.crawl()`, `wait_crawl()`, `get_crawl_status()`, and `get_crawl_status_page()` now populate `CrawlJob.id` and `CrawlJob.warning`, so callers can call `get_crawl_errors()` / `cancel_crawl()` on the returned job and see the `warning` the status API already surfaces (robots blocks, truncated results, etc.).
- **Python SDK typed scrape failures** — DNS and TLS scrape failures now raise dedicated `ScrapeDNSResolutionError` and `ScrapeTLSHandshakeError` exceptions carrying `url` and `code`, instead of generic `FirecrawlError`s. Exception mapping is now driven by the API's `code` field so new scrape error codes stay typed.
- **PHP SDK Laravel AI tools** — Added a Laravel AI SDK tool base class plus `FirecrawlScrape`, `FirecrawlSearch`, `FirecrawlCrawl`, `FirecrawlMap`, and a `FirecrawlTools::all()` helper. Output size, deadline, and crawl-wait budgets are bounded so long-running jobs stay queue-friendly.
- **Python SDK request origin** — Added an optional `origin=` on `Firecrawl` / `AsyncFirecrawl` and the v2 HTTP clients so integrators (Arcade, LangChain plugins, …) can stamp their own attribution instead of the hardcoded `python-sdk@version`, including on the research GET helpers.
- **Python SDK `get_agent_thread`** — Exposed `get_agent_thread(thread_id)` and its async equivalent on `Firecrawl` / `AsyncFirecrawl`, closing a parity gap with the HTTP API's thread-reconstruction endpoint.
- **JS SDK `webhook` on extract** — Added a `webhook` option to `startExtract()` and `extract()` on the JavaScript SDK, matching the other job-starting methods.
- **In-app notifications for monitor and dashboard activity** — The API now writes `user_notifications` rows for monitor state changes and dashboard-origin crawl completion, so the dashboard's notification center picks them up without any extra polling. Deduped per team and job, idempotent across retries, and a no-op on self-hosted deployments.
- **Node runtime metrics** — The app and worker `/metrics` endpoints now export `nodejs_eventloop_lag_seconds` (plus p50/p90/p99), heap, resident-set, and GC counters from prom-client's default collectors, so event-loop stalls, memory pressure, and GC pauses are visible in Prometheus and in whatever tooling scrapes it.
- **Canonical auth-denied log line** — Every request authentication refuses (missing key, unknown or malformed key, banned team, IP or endpoint restriction, …) now emits a single `warn` line with `canonicalLog: "auth/denied"`, HTTP status, route pattern, reason, and `teamId` / `apiKeyId` when a real key resolved. Previously these denials left no trace in the API's own logs.
- **Alexandria feedback window and refund** — `POST /v2/feedback` with `endpoint: "alexandria"` now refunds 1 credit per feedback (any rating), capped at 10 refunds per team / requested website / UTC day, and must arrive within `ALEXANDRIA_FEEDBACK_WINDOW_SEC` (default 20 minutes) of the team's latest Alexandria call — otherwise it returns `409 FEEDBACK_WINDOW_EXPIRED`. The existing 2-minute search-feedback window is unchanged for search and endpoint feedback.
- **`metadata.provider` on Exchange scrapes** — Documents served by the Alexandria Exchange now carry `metadata.provider` with the serving provider `id`, the Exchange `creditsCost`, and the ordered `steps` list from the enrichment waterfall, so callers can see which third-party provider returned the data and why the price differs from a plain scrape. The Rust SDK's `DocumentMetadata` adds a typed `provider` field for the same payload.
- **Caller credential forwarding to the Exchange** — The caller's `Authorization` header is now forwarded to the Exchange on every provider-tool execution (not just the earlier Bash, SQL, and enrichment paths), so Exchange tools that call Firecrawl back as the caller can authenticate for any request. The credential is never sent with quote or authorization calls and is never persisted.
- **Autumn concurrency and rate-limit caching** — The API now caches each team's Autumn concurrency limit, rate-limit multiplier, and paid-plan status on the ACUC chunk and reads them straight off the chunk instead of calling Autumn on every rate-limit decision. Fail-open values apply when Autumn is unreachable, so a provider outage no longer drops teams to the free-plan floor.
- **Team flag overrides** — The API now reads a team's feature flags through `auth_chunk_2`, which merges per-team `teams.flags` overrides on top of the organization flags. Teams can enable or disable a flag independently of the rest of their org without a dashboard change.
- **Larger crawl path filters** — Raised the `includePaths` / `excludePaths` cap on `POST /v2/crawl` and `POST /v1/crawl` from 100 patterns to 1000, with the compilation cost of each set bounded.

## Fixes

- Resolved multiple CVEs across the API, SDKs, and self-host images including `undici`, `multer`, `fast-uri`, `ip-address`, `axios`, `postcss-selector-parser`, `systeminformation`, `sharp`, `fflate`, `js-yaml`, `tinyvec`, `rustls-webpki`, `rand`, `http-cache-semantics`, `golang.org/x/net`, and `golang.org/x/sys` through repeated `pnpm audit` / Dependabot sweeps and a scoped `geoip-country>ip-address` override.
- Fixed `POST /v2/monitor` cron validation stepping forward one minute at a time, which spent 25–60 seconds of synchronous work on the event loop for yearly crons and caused app pods to miss liveness probes; validation now jumps days and hours and the `POST /monitor` p50 dropped from 27s to 48ms.
- Fixed the JavaScript, Python, Go, Rust, Java, and Elixir SDKs forwarding the API key to cross-host `next` pagination URLs — pagination now pins absolute `next` targets to the configured `api_url` origin, so a crawl, batch scrape, or monitor status response pointed at another host no longer receives `Authorization: Bearer <key>`.
- Fixed the Go, Java, .NET, Ruby, and PHP SDKs mishandling `success: false` scrape responses (such as `SCRAPE_DNS_RESOLUTION_ERROR`) that the API returns as HTTP 200 — these SDKs now raise a typed error with the API's message and code instead of silently returning an empty document or losing the error payload.
- Fixed the JavaScript SDK's `v1` methods crashing when called without optional params, and v1 `batchScrapeUrls` polling the `/v1/scrape` status endpoint instead of `/v1/batch/scrape/{id}`.
- Fixed the Python SDK's v1 `batch_scrape_urls` polling the `/v1/scrape` status endpoint instead of `/v1/batch/scrape/{id}`.
- Fixed the JavaScript and Python Alexandria SDK clients timing out at 80s while the API runs executions to 120s and bills the late success — SDK execution timeouts now match the API's 120s cap.
- Fixed self-hosted and proxied deployments bypassing the SSRF check in `safeFetch` — undici's `ProxyAgent` never emits the socket-level `connect` event, so private IP literals and `localhost` names (including `*.localhost` and trailing-dot forms) are now rejected by an interceptor before the proxy tunnel on every redirect hop.
- Fixed the Playwright engine always echoing the requested URL in `metadata.url`, which silently disabled the threat-protection redirect re-check, the post-redirect blocklist re-check, and the cross-hostname crawl origin update on self-hosted deployments.
- Fixed `GET /v1|v2/crawl/:id` and `/batch/scrape/:id` returning a `next` cursor that pointed back at the same page on cancelled and failed jobs, which caused SDK auto-pagination to spin forever.
- Fixed `POST /v2/batch/scrape` refusing Exchange-eligible blocklisted URLs (e.g. a `linkedin.com/in/<handle>` the caller is entitled to) with a generic `UNSUPPORTED_SITE` 403 — batch scrape now runs the same Exchange gate as `/v2/scrape` and routes those URLs through the exchange engine.
- Fixed the blocklist's `allowedKeywords` substring match exempting URLs that a catalog provider claims (for example `linkedin.com/company/<slug>/about/` was treated as unblocked because `about` is an allowed keyword), which caused those requests to miss the Exchange and surface a 500 `SCRAPE_ALL_ENGINES_FAILED`. Allowed keywords no longer exempt claimed URLs.
- Fixed `/v2/scrape` returning a misleading `500` for Exchange `not_found` (provider has no such record) and `invalid_exchange_url` (sub-pages of a supported record like `linkedin.com/in/<handle>/details/…`) — these now surface as `404 THIRD_PARTY_DATA_NOT_FOUND` and `400 THIRD_PARTY_DATA_UNSUPPORTED_URL`.
- Fixed `POST /v2/crawl` scraping the start URL before its robots.txt was checked — the start URL is now evaluated against robots before the fetch, matching every other crawl URL. Sitemap, index, and redirect robots blocks are also now recorded for the status warning and `/errors`.
- Fixed `GET /v2/crawl/:id` never showing the robots warning and `robotsBlocked` being empty on `/errors` — the worker now matches both the scrape and crawler denial texts and link extraction defers robots filtering so `filterLinks` can report blocked discovered links.
- Fixed `GET /v2/crawl/:id` and `GET /v2/batch/scrape/:id` reporting `completedAt == createdAt` and `duration: 0` when no page succeeded (for example, the start URL failed) — `completedAt` is now the finish time of the latest job of any outcome.
- Fixed JSON-format extraction failing on wrapper schemas without the agent, on content past the model's context window, and on schemas strict mode rejects (missing `items`, bare property maps, `"type": "String"`); the SmartScrape envelope is now applied only when `useAgent: true`, content is trimmed to the real `max_input_tokens`, and self-hosted models honor a new `MODEL_MAX_INPUT_TOKENS` budget.
- Fixed JSON extraction wasting roughly four minutes per request when the response was cut off at the model's output cap — truncated JSON is detected and the "repair" call is skipped, so the request fails fast with a clear "exceeded the model's maximum output length" warning instead of a second truncated attempt.
- Fixed hosted-MCP agent runs 401'ing on every downstream `/v2/browser`, `/v2/search`, `/v2/scrape`, and `/v2/batch/scrape` call because the default key lookup skipped `hosted_mcp_oauth` credentials.
- Fixed agent browser creation returning `429 "maximum number of concurrent jobs (2)"` on free-plan teams — trusted agent-interop traffic now floors browser concurrency at the hobby limit (`HOBBY_CONCURRENCY_LIMIT = 5`), matching the rate limiter's existing hobby floor.
- Fixed X/Twitter profile scrapes letting the model pick among multiple candidate accounts (which xAI billed per profile) and silently returning the wrong account; profile scrapes now look up the exact handle with a single 1-result user search and drop mismatched usernames.
- Fixed X/Twitter monitor credit estimates missing the engine's `+29` credit per-page surcharge, which let low-balance accounts reserve 2 credits for a 31-credit check and run monitors indefinitely without ever being charged.
- Fixed monitors reserving one credit per PDF URL and under-reserving by hundreds of credits on repeat checks; reservations now add known page counts from the previous successful run, honoring parser settings, `maxPages`, removed scrape URLs, and reduced crawl limits.
- Fixed FirePDF `POST /jobs` returning `400 invalid_pages_estimate` when the router had no page count; `pages_estimate` is now omitted in that case and fire-pdf counts the pages itself.
- Fixed the `branding` format failing the whole scrape with `BrandingNotSupportedError` on PDFs, documents, and images in crawls and batch scrapes — branding is now skipped with a warning while the other requested formats return normally.
- Fixed the `branding` format leaking internal `__llm_logo_reasoning`, `__llm_button_reasoning`, and `__llm_metadata` fields in production responses; every `__`-prefixed key is now stripped unless `DEBUG_BRANDING` or the `debugBranding` team flag is on.
- Fixed the `branding` format discarding valid LLM results on schema mismatches, running its in-page scan twice per page, and dropping LLM telemetry under zero data retention.
- Fixed the `branding` format picking a secondary button that the response's post-processing merge would discard, which could blank out the field on some pages.
- Fixed the prompt-injection guard billing customers when a classifier chunk failed open — unscanned chunks now record a `"none"` verdict, the guard fee only bills when every chunk has a verdict, and the response `warning` surfaces incomplete scans.
- Fixed `GET /v2/agent` returning stale `options` payloads that dropped `threadId` and `threadTurn`, so threaded runs can be grouped in the dashboard sidebar.
- Fixed enhanced-proxy scrapes being surcharged `+4` credits when no proxy egress actually occurred.
- Fixed billing dropping the Lockdown surcharge on `json`-format scrapes.
- Fixed scrapes that fail DNS resolution being billed.
- Fixed v2 batch scrape charges dropping the caller's `x-request-id` so idempotent replays could not line up with their original charge rows.
- Fixed Alexandria feedback having no time window — a team could send feedback (and get a refund) at any time; late feedback now returns `409 FEEDBACK_WINDOW_EXPIRED` just like late search feedback.
- Fixed screenshot signed URLs returning stale results from cache after key rotation by forcing a re-sign when the signed URL expires.
- Fixed `/map` dropping the first URL of each sitemap and starving sitemap-index children of the fetch budget.
- Fixed `/search` `includeDomains` double-parenthesizing `site:` expressions upstream and failing to pass domain filters through to the search engine.
- Fixed lazy-loaded images not resolving from `data-srcset` and `data-src` attributes.
- Fixed `text/plain` markdown output escaping underscores.
- Fixed empty FirePDF results being served and stored for raster images, and PDFs under 4 KiB now fall back to `pdf-parse` instead of returning nothing.
- Fixed mislabeled PDF and Office downloads by routing them through their magic bytes on the `POST /scrape` fast path.
- Fixed `SCRAPE_ACTIONS_NOT_SUPPORTED` being thrown after a document or PDF prefetch when actions should have been skipped.
- Fixed DOCX parse output dropping headers and footers.
- Fixed monitor webhooks being finalized twice for the same check.
- Fixed `POST /v2/crawl` following external-link redirects onto subdomains within their own domain instead of terminating the crawl.
- Fixed `POST /v1/status/:jobId` and related endpoints returning `500` on non-UUIDv7 job IDs — malformed ids now return `404` ("job not found") instead of leaking as a Bigtable outage.
- Fixed a stack overflow in native PDF extraction by running it off the Node.js event loop with a bounded concurrency semaphore.
- Fixed per-key spend limits returning `500` on denial — now returns `402` with a clear message.
- Fixed HTML transformations being applied to sitemap XML.
- Fixed keyless authentication errors to point at signup and the `Bearer` scheme.
- Fixed `query` and `highlights` prompts exceeding the model's context window on long pages; prompts are now trimmed per-model.
- Fixed the Rust SDK failing to parse crawl and batch scrape status responses with negative `creditsUsed`; unknown agent models now degrade instead of aborting the parse.
- Fixed the unsupported-site error pointing at the legacy Typeform intake instead of https://www.firecrawl.dev/contact-sales.

## API

- Added the `alexandria` source and `domainTools` to `POST /v2/search` and `POST /v2/scrape`. Discovery returns tool contracts in `data.tools` and is free. Execution takes an `alexandria` body of one to ten calls on `POST /v2/scrape`, returns `data.alexandria[]`, `data.creditsCost`, and `scrape_id`, and uses `x-request-id` as its idempotency key. A `403 THIRD_PARTY_DATA_TERMS_REQUIRED` exposes `requiresAction` with the terms URL and version.
- Added `metadata.provider` on Exchange-served scrape documents with `{ id, creditsCost, steps: [{ provider, status, creditsCost? }] }`. The Rust SDK's `DocumentMetadata` exposes a typed `provider` field.
- Added `agent_hints: string[]` on v2 `/scrape`, `/search`, `/parse`, and `/map` responses when a response-guidance provider is configured, capped at three hints per response. The `X-Firecrawl-Agent-Hints` header is now **opt-in**: send `X-Firecrawl-Agent-Hints: true` to request hints. Without a configured provider (including default self-hosted deployments) responses carry no `agent_hints`.
- Added `menu` to v1 and v2 scrape formats and populated `document.menu` when the scrape succeeds; requires the `menuBeta` team flag.
- Added `safe: boolean` to `POST /v2/search`. Non-boolean values are rejected with a schema error.
- Added optional `objective` (string) and `clientModel` (string) on `POST /v2/search`. Invalid values are ignored, not rejected.
- Added `GET /v2/parse/formats`. Returns `{ formats: [{ format, kind, extensions, mimeTypes, available }] }`, where `kind` is `document` or `image`. Available on every SDK as `getParseFormats` / `get_parse_formats` / `GetParseFormats`.
- Added `POST | GET /v2/search/gov` and the `gov` category on `POST /v2/search`. Accepts `{ query, k? }` with `k: 1–100` and returns `{ web: [{ url, title, description, position }] }`. Gov searches are free (0 credits) and keyless-friendly. Mounts only when `SEARCH_PLATFORM_URL` is configured.
- Added `blockAds: boolean` (default `true`) on `POST /v2/browser` so interact and browser sessions can opt out of the always-on blocker. New Interact sessions inherit the scrape's `blockAds`; sessions adopted via `existingSessionId` keep their own setting.
- Added `zeroDataRetention: true` on `POST /v2/interact` and `POST /v2/browser`. ZDR sessions reject `recordSession` and saved profiles, strip request bodies from credit denial and clamping logs, and route prompts through a non-logging provider. Forced-ZDR teams get ZDR automatically.
- Added `safeModeConfig` and org-level Safe Mode enforcement. Requests that touch blocked capabilities return `403 SAFE_MODE_BLOCKED`; restricted sites terminate with `SCRAPE_SITE_RESTRICTION_BLOCKED`. Per-request bypass requires `allowBypassSafeMode`.
- Added `threatProtection` team flag with modes `off`, `normal`, and `zscaler`. Enforced across `/scrape`, `/batch/scrape`, `/crawl`, `/search`, `/map`, `/extract`, and `/agent` (v1 + v2). Billing: `+2` credits per unique scanned canonical URL per billing scope. JavaScript and Python SDKs expose the full `threatProtection.mode` enum, including `manual-only` and `zscaler`.
- Added the `ipRestriction` team flag and `ip_restriction_config` allowlist. Unlisted IPs from API-key or `fco_` OAuth tokens are rejected with `403`; empty lists remain unrestricted so teams cannot lock themselves out before configuring.
- Added the `keyRestriction` team flag and `key_restriction_config` per-key allowlists for `allowed_formats` and `allowed_endpoints`. Unknown endpoints and legacy `/v0` endpoints fail closed for restricted keys.
- Added `POST /v2/interact/:sessionId/replay` and `POST /v2/interact/:sessionId/replay/:pageId` (also under `/v2/browser/...`), returning HLS `.m3u8` playlists with pre-signed segments. `POST /v2/interact` accepts `recordSession` (default `false`); `scrape-interact` responses now include `sessionId`.
- Added `DELETE /v2/browser/profiles/:name` and `DELETE /v2/interact/profiles/:name`. Deleting a profile with no saved state succeeds; a session actively saving to the profile returns `409`.
- Added `GET /v2/agent` cursor-paginated list. Accepts `before`; returns 20 runs per page with a `next` URL only when more pages exist. Malformed `before` values are rejected with `400`. Available on every agent-supporting SDK as `listAgents` / `list_agents`.
- Added `partial`, `partialSchemaValid`, and `stopReason` on failed `GET /v2/agent/:id` responses (and in the thread history) so callers can inspect best-effort partials when a run halts on credits or a tool error.
- Added `effort: "low" | "medium" | "high"` on `POST /v2/agent`. `effort` and `model` together return `400`; `effort` alone runs `spark-2`; `model` alone keeps the requested preset. The `GET /v2/agent/:id` status response includes an optional `effort` field.
- Added `exchange.onTermsRequired: "skip" | "ask"` on `POST /v2/agent`. Any other value, including `"fail"`, is rejected with `400`; follow-up turns inherit the previous value from the thread. `GET /v2/agent/:id` returns `onTermsRequired`, `skippedProviders[]`, and `requiresAction.approvalId` on `AgentExchangeSummary`, and `AgentPendingApproval` is now a `{ kind: "calls" } | { kind: "terms" }` union.
- Added `GET /v2/agent/:id/trace` (with `liveView`) and `GET /v2/agent/:id/snapshots/:snapshotId`. All 13 public trace event types are versioned against the agent service's canonical event schema v1.
- Added `checkPromptInjection: boolean` to JSON-mode extraction on v1 `jsonOptions` / `extract` and v2 `formats: [{ type: "json" }]`. Errors with `SCRAPE_PROMPT_INJECTION_DETECTED` (`403`) on detection; billing adds `+4` credits when the check runs cleanly and does not bill when the guard fails open.
- Added `parsers[].pageMarkers`, `parsers[].pages`, and `parsers[].blocks` on the PDF parser. Renamed the earlier `parsers[].pageMarkdown` to `pages` (transformation alias kept for compatibility). `parsers[].totalPages` is now reported on truncated PDFs.
- Added `rawBase64` to v2 scrape formats.
- Added `country` on `POST /v2/search` across the JavaScript, Python, Go, Rust, Ruby, Java, and PHP SDKs.
- Added `objective` (trimmed, 1–2000 characters) on `POST /v2/feedback` with `endpoint: "alexandria"`, distinct from `requestedWebsite.requestedFunctionality`.
- Added Alexandria feedback refund and window on `POST /v2/feedback` with `endpoint: "alexandria"`: 1-credit refund per rating (`good`, `partial`, `bad`), capped at `ALEXANDRIA_FEEDBACK_WEBSITE_DAILY_CAP_CREDITS` (default 10) per team / requested website / UTC day. Feedback outside `ALEXANDRIA_FEEDBACK_WINDOW_SEC` (default 1200s) of the team's latest Alexandria call returns `409 FEEDBACK_WINDOW_EXPIRED`.
- Added two new public error codes raised by the Exchange engine, `THIRD_PARTY_DATA_NOT_FOUND` (404, record not found) and `THIRD_PARTY_DATA_NOT_ENABLED` (403, provider not entitled), and `requiresAction` on `GET /v1|v2/crawl/:id/errors` and `/batch/scrape/:id/errors` entries that need terms acceptance.
- Added `THIRD_PARTY_DATA_UNSUPPORTED_OPTION` (`400`), returned when a request to a provider-claimed URL carries an option the Exchange cannot honor, so callers see which option to drop instead of the generic unsupported-site message.
- Changed Exchange refusal mapping on `/v1|v2/scrape`: `not_found` → `404 THIRD_PARTY_DATA_NOT_FOUND`, `invalid_exchange_url` → `400 THIRD_PARTY_DATA_UNSUPPORTED_URL` (previously both surfaced as `500`).
- Changed `POST /v1|v2/scrape` and `/crawl` to serve Exchange-provider URLs with the normal engines on **every** route when the URL is not blocklisted — previously these two routes returned `403 THIRD_PARTY_DATA_TERMS_REQUIRED` on provider URLs that batch scrape, search-with-scrape, extract, monitors, and crawl-discovered pages already served normally.
- Changed `POST /v2/batch/scrape` to admit Exchange-eligible blocklisted URLs through the exchange engine, matching the gate that already existed on `/v2/scrape`.
- Changed non-UUIDv7 job IDs on `POST /v1/status/:jobId` and related endpoints to return `404` ("job not found") instead of `500`.
- Deprecated the `spark-1-pro` and `spark-1-mini` agent models. The names continue to be accepted on `POST /v2/agent` (rewritten to `spark-2`) and remain in every SDK's model type for compile compatibility; they are marked deprecated in the SDK doc comments.

- Allowed `screenshot` and `pdf` action variants on Zero-Data-Retention scrapes.
- Raised the `includePaths` / `excludePaths` cap on `POST /v2/crawl` and `POST /v1/crawl` from 100 to 1000 patterns; regexes the engine cannot honor are now rejected up front.
- Changed the per-key spend-limit denial to return `402` (previously surfaced as a `500`).
